# MVP scope

## Purpose

Validate whether a short, user-controlled message can reduce silence, guilt and relationship misunderstanding during temporary loss of communication capacity.

## The complete MVP

The MVP consists of two complete journeys:

### Create a Hold

- choose one or more people
- choose an intent
- receive a short draft
- edit it
- review names and message together
- open the native share sheet
- see a calm completion state

### Return from Hold

- choose one or more people
- choose how much to say
- receive a short draft
- edit it
- open the native share sheet
- see a non-guilting completion state

## Supporting MVP requirements

- plain-language privacy explanation
- no automatic sending
- no diagnosis required
- no mandatory return date
- accessible text and controls
- reduced-motion compatible
- recoverable error copy
- usable without an account
- usable without live AI

## What “AI help” means at MVP stage

The value proposition may describe help drafting messages, but the first testable build should use curated local drafts. This lets the team validate the journey before adding:

- model cost;
- sensitive data transfer;
- server infrastructure;
- moderation;
- latency;
- retention risk; and
- variable output quality.

Live AI is a later implementation milestone, not necessary to prove the core product need.

## Acceptance criteria

A test participant can complete either journey without help and can accurately state:

- what the app will do;
- who will receive the message;
- that nothing is sent automatically;
- that they can edit every word; and
- that no reason or diagnosis is required.
